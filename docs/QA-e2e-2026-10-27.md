# E2E GUI test report, 2026-10-27

Page under test: `site/dist/index.html` built from `site/src/index.html` at commit `a3f9fa1` (the v3 design). All line numbers below refer to `site/src/index.html`.

## How the test ran

- Headless Chromium 154 through `playwright-cli` 0.1.22, one isolated session per tester, against `python3 -m http.server -d site/dist 8765`. One pass also loaded the page from `file://`.
- Five scoped testers (Opus agents) covered Browse, Compare, Detail, state and routing, and responsive layout with dark theme and accessibility. Each tester compared the UI against the data inlined in `#atlas-data`, not against expectations.
- The orchestrator (Fable) re-ran every S2 finding and the most visible S3 findings in a separate clean session. The "Verified" line of each finding says who reproduced it.
- The raw reports with full evidence read-outs sit in `docs/qa-e2e-2026-10-27/`: the first round (`browse.md`, `compare.md`, `detail.md`, `state.md`, `responsive.md`), the re-test after the fixes (`regress-*.md`), and the features round (`feat-*.md`). The tester brief, the fix notes and the features spec are there too (`tester-brief.md`, `fix-notes.md`, `features-spec.md`). Screenshots and scripts stayed in the session scratchpad and are not in the repo; the `/tmp/claude-1000/...` paths cited in those reports point to that temporary directory.
- Severity: S1 blocker, S2 major, S3 minor, S4 note. The scale is in the raw reports.

Top risks, in order:

3. The Browse reference model: a pinned row that ignores filters and a reference that can be set without any visible sign (findings 5 and 6).
4. Keyboard users lose focus after most actions on every screen (finding 8).

## S2 findings

### 1. Compare grid is wider than the window from 760 to about 890 px
- Where: Compare, 4 grid columns (4 devices, or 3 plus the add slot), widths 760 to about 890 px.
- Steps: clear storage, set the viewport to 800×900, open `#compare`.
- Actual: the grid needs 860 px (`180px + 4 × minmax(170px, 1fr)`), the panel is 712 to 832 px wide and is not a scroll container above 759 px. `documentElement.scrollWidth` is 885 at 760, 800, 850 and 880 px. The fourth column is cut at the window edge and the whole page scrolls sideways. This breaks CONTRACT "Responsive".
- Code: `gridHtml` line 1128 to 1129 and 1141; `.scroll` is added only when `innerWidth < 760` (line 774).
- Verified: tester (4 runs) and orchestrator (885/800, 885/760, 899/899).

### 2. Dropdown rows grow past the dropdown box: page scrolls sideways
- Where: header search `#hq-dd` at 400 px (and labels paint outside the box at 1280 px); Compare add-slot `#sq-dd` at 1280 and 1440 px.
- Steps: with a free queue slot, type `ayaneo air` in `#hq` at 400×800; or remove one device on Compare and type `ayaneo` in `#sq` at 1280×800.
- Actual: every `.dd-item` takes the width of the longest sub-line. At 400 px the box ends at x 384, the rows end at x 475, the seven "+ Compare" labels sit off-screen and `scrollWidth` is 475. On Compare at 1280 px the rows reach x 1465 (`scrollWidth` 1465). The `text-overflow: ellipsis` on `.dd-s` never applies.
- Code: `.dd { display: grid }` (line 105) has no column template, so items keep `min-width: auto`; `.dd-s { white-space: nowrap }` (line 111). A fix is `grid-template-columns: minmax(0, 1fr)` on `.dd` or `min-width: 0` on `.dd-item`.
- Verified: two testers and orchestrator (400 px: dd right 384, items 475, scrollWidth 475; 1280 px: items 1465).

### 3. Compare add-slot dropdown is anchored to the slot and runs past the right edge
- Where: Compare with 2 or 3 devices, 960, 1280 and 1440 px; clipped by the scroll container at 400 px.
- Steps: remove one device, type any query in `#sq`.
- Actual: the 320 px box starts at the slot's left edge (x 1006 at 1280 px) and ends at x 1326, past the viewport even for short results. At 400 px the box (x 246 to 566) is cut at x 384 by `.cmpw.scroll`, so only 138 of 320 px show.
- Code: `.cslot .dd { left: 12px; right: auto; width: min(320px, calc(100vw - 48px)) }` (line 315).
- Verified: two testers and orchestrator (screenshot at 1280 px).

### 4. Below 760 px the Compare grid header covers the first rows and does not stick
- Where: Compare, every width under 760 px.
- Steps: clear storage, set the viewport to 400×800, open `#compare`, scroll to the grid.
- Actual: the header row is drawn 130 px (the value of `--hdr-h`) below the panel top. It overlays "Overview", "MSRP", "Released" and most of "Form factor". While the page scrolls, the row does not stick (top −212 at scrollY 1300). At 760 px and above it sits at the panel top and sticks at 53 px.
- Code: `.cgrid.hd { position: sticky; top: calc(var(--hdr-h) …) }` (line 300) inside `.cmpw.scroll { overflow-x: auto }` (line 298). The overflow container becomes the sticky scroll root. It never scrolls vertically, so the `top` offset only pushes the row down.
- Verified: two testers and orchestrator (offset 131 px, screenshot).

### 5. Reference row stays pinned when it fails the filters; count and empty state disagree
- Where: Browse table and cards, any width.
- Steps: clear storage (reference is Steam Deck OLED), tick brand Valve, then stick type TMR.
- Actual: `#lbar-n` reads "0 devices", one row shows (Steam Deck OLED), `#empty` stays hidden, so its reset button is unreachable. With brand GPD: label 26, rows 27; "Show all 33 devices" against "32 devices".
- Code: `applyList` line 1010 `list.unshift(ref)` with no filter check; lines 1016 to 1019 use `list.length`, line 1021 uses `filt.length`.
- Verified: tester and orchestrator.

### 6. Adding a device while no reference is set creates a hidden reference
- Where: Browse, row checkbox, header search, card button.
- Steps: clear storage, click `#ref-clear`, untick then re-tick `#q-rog-xbox-ally-x`.
- Actual: storage holds `refId: "rog-xbox-ally-x"`, but there is no reference pill, no `tr.ref`, and no delta pill until a reload. With a filter on, the row jumps to the top with no reference style.
- Code: `addQ` line 815 sets `state.refId` and calls `afterQ()` (line 806), which does not rebuild rows; `afterRef()` (line 830) does.
- Verified: tester and orchestrator.

### 7. Detail "Sources" group clips notes and URLs
- Where: Detail, Sources group, 39 of 134 sheets at 1280 px, 37 at 400 px (for example `#ayaneo-2`, `#ayaneo-flip-1s-ds-8840u`).
- Actual: a raw URL inside a note makes the `li` grow to 454 px inside a 280 px panel; `.grp { overflow: hidden }` cuts the right part of every line in the list, including short notes.
- Code: `.dl .why` (line 377) lacks `overflow-wrap: anywhere` (only `.dl .url` at line 378 has it); `.dl` is a grid (line 375); `.grp` clips (line 364).
- Verified: tester and orchestrator (panel 280 px, scrollWidth 466, li 454).

### 8. Keyboard focus drops to `body` after most actions
- Where: every screen. The next Tab then starts over from the top of the screen or lands on the footer link and scrolls the page away.
- Controls that lose focus:
  - Browse: `#ref-<id>`, `#cref-<id>`, `#ref-clear` (rows rebuilt); `#lay-table`, `#lay-cards`, `#more-btn`, the queue popover remove and Clear buttons, the empty-state Reset.
  - Compare: `#hide-same`, `#size-open`, `#tab-2d`, `#tab-3d`, every `#view-*` and `#mode-*` chip, `.ccol` set-reference (click, Enter, Space), `#crm-<id>`, "Show all rows". The 3D preset chips keep focus.
  - Detail: `#dt-add`, `#dt-ref`, "← Back to list" (next Tab goes to the footer and scrolls to the bottom, 9,294 px in one run).
  - Route buttons: queue popover "Open comparison", Compare "← Back to list", Detail "Open comparison (n)", Compare empty-state "list".
- Code: `renderCompare` (1037), `renderDetail` (1352), `buildRows` and `renderListBar` via `afterRef` (830), `renderQpop` (869) replace the focused node; `go()` (1382 to 1400) hides the screen that holds the button and focuses only `#dt-h1` on Detail. The `sort`, `grp` and `chip` cases restore focus (1435 to 1437) and show the pattern to copy.
- Verified: four testers and orchestrator (`#ref-`, `#view-top`, `#dt-ref`, Back to list).

### 9. A stored sort key such as `constructor` throws at boot
- Where: boot, any screen. Needs `localStorage["handheld-atlas:v3"].sortK` set to an `Object.prototype` member. No UI control writes such a value, which is why this is S2 and not S1.
- Actual: uncaught `TypeError: c.v is not a function` in `sorted` (line 933) stops the init: no hash rewrite, badge `0/4` with devices queued, 134 unsorted rows, no row limit, no pinned reference. Every reload fails until the user clicks a sort header.
- Code: `loadState` line 740 `if (COL[s.sortK])` accepts inherited keys; `COL` is a plain object (line 654).
- Verified: tester (3 runs) and orchestrator (pageerror seen).

## S3 findings

### 10. Delta percent rounds negative half values toward zero
- `Math.abs(Math.round(p))` (line 628): `Math.round(-19.5)` is −19, so −19.5 % shows "▼ 19%" while +19.5 % shows "▲ 20%". Seen on 1 to 15 table pills per reference and 17 of 58 Compare combinations (for example Steam Deck OLED 50 Wh vs Ally X 80 Wh shows "▼ 37%", expected 38 %). Affects table, cards, Compare grid, legend and PassMark pills. Fix: `Math.round(Math.abs(p))`. Verified: two testers and orchestrator.

### 11. Theme button icon never changes
- `syncThemeBtn` (line 782) sets `.hidden` on two `<svg>` elements. `SVGElement` has no `hidden` property, so the markup attribute never changes: the moon shows in dark mode too. The label and title do switch. Fix: `toggleAttribute("hidden", …)` or wrap the icons in `<span>`. The CONTRACT line "Toggle visibility with `el.hidden`" needs the same caveat. Verified: two testers and orchestrator.

### 12. A `?theme=` URL erases the saved theme
- `loadState` line 760 overwrites the loaded theme with the forced one; `save()` line 767 then writes `theme: null` on the first `go()`. A user who picked dark, opens `?theme=light` once, and comes back gets the system theme. Same on `file://`. Verified: tester and orchestrator.

### 13. `Object.prototype` keys pass the device and filter lookups
- URL `#constructor`, `#__proto__`, `#toString`, `#hasOwnProperty`: a blank sheet renders ("Outline of , spec box", "0 × 0 × 0 mm", every field "Not stated"), `detailId` is persisted, so a plain load reopens it; "Set as reference" on it has `data-id=""` and clears the real reference.
- Stored queue or `refId` with such ids (also kept by the v1/v2 migration): three blank Compare columns, badge `4/4` with no add slot, pill "Reference: ", "Show all 135 devices". A stored `sizeView: "constructor"` labels the stage "function Object() …"; a stored brand filter `["constructor"]` shows the empty state.
- Code: `BY_ID` (503), `COL` (654), `CNT.*` via `count` (711), `VIEW_NAME`; checks at 737, 739, 743, 755, 759, 1383, 1405. One fix: build these maps with `Object.create(null)` or guard with `Object.hasOwn`. Verified: two testers and orchestrator (`#constructor`).

### 14. An unknown hash set while a sheet is open leaves the old sheet with a wrong URL
- `routeFromHash` (1402 to 1408) returns false for an unknown token and the `hashchange` listener ignores it. Edit the address to `#no-such-device` on a sheet: the sheet stays, the URL is wrong. A fresh load of the same hash falls back to Browse. Verified: tester (2 runs); matches the code.

### 15. Source popover note text runs outside the box
- `#pop .why` (line 383) lacks `overflow-wrap: anywhere`. On 11 sheets a URL in a note runs to x 1304 in a 1280 px window (for example `#ayaneo-air-1s-7840u`, the `$899` value) and off-screen at 400 px. Verified: two testers.

### 16. The open popover stays fixed while the page scrolls
- `#pop { position: fixed }` (line 380); only `resize` closes it (line 1513). After a 300 px wheel scroll the popover points at an unrelated row. Verified: tester (2 runs).

### 17. Popover links are unreachable by keyboard
- `openPop` (1358) does not move focus; `#pop` is the last element in `body` (line 478), so Tab from the value goes to the next value and the dialog stays open. Verified: tester (2 runs).

### 18. The list can be sorted by a hidden column with no indicator
- Hide the Performance group while sorted by G3D: order unchanged, no `aria-sort`, no arrow. Remove every group and reload: `loadState` restores the default groups (line 750) but keeps `sortK` (for example `stick`), so the active sort is invisible and cannot be toggled. Code: `grp` case (1436) does not check `sortK` against `visCols()`. Verified: tester.

### 19. Default table overflows its wrapper at 1280 px; the Ref column is off-screen
- 1333 px table in a 982 px wrapper at 1280×800 with the default groups (351 px hidden: part of Refresh, all of RAM, SSD, Battery and Ref). 1574 px in 1142 px at 1440×900 with all groups. The only scrollbar is at the bottom of `#tblw`; no sticky device column or scroll cue. Not a CONTRACT violation (the body does not scroll). Verified: tester and orchestrator (982 vs 1333).

### 20. Header search matches stray digits and keeps data order
- `searchDevs` (850 to 854) is a per-token substring test with no ranking. `win 5` lists three GPD Win 4 variants (the `5` matches "Ryzen 5" and "2025") before GPD Win 5; `claw 8` lists Claw 7 AI+ first; `onexplayer 2` fills the 8-item cap and drops four X2 variants. Verified: tester and orchestrator probe.

### 21. "1 devices"
- `renderListBar` (949), `applyList` (1021) and the more button (1017) append " devices" with no plural check. Verified: tester.

### 22. Compare labels its fallback column "Reference" when the global reference is not in the queue
- `renderCompare` line 1040 falls back to column 1 and labels it "Reference" with `aria-pressed="true"` and "REF" in the legend, while the Browse pill names another device (for example Steam Deck LCD). The one global reference is intended; the silent label is the defect. Verified: tester (2 runs).

### 23. Compare column header is a `role="button"` that wraps two real buttons
- `gridHtml` line 1145: `.ccol[role=button]` contains the remove button and the open button (axe "nested-interactive"). Mouse and keyboard work. Verified: two testers.

### 24. Keyboard moves can leave two floating layers open
- Open the queue popover with Enter, Shift+Tab into `#hq`, type: `#qpop` and `#hq-dd` are both open. Same for a source popover plus the search dropdown. Only the click handler closes other layers (1411 to 1422); `focusin` (1474) and `input` (1469) do not. Verified: tester (2 runs).

### 25. Search dropdown: Tab past the last item leaves it open; Escape on an item drops focus to `body`
- `focusout` (1475 to 1480) acts only when the target is the input; the Escape branch (1459) calls `hideDD()` without refocusing `#hq`. Verified: tester (2 runs).

### 26. Two tabs overwrite each other's saved state
- `save()` (762) writes the whole in-memory state on every change; there is no `storage` listener. A device removed in tab A comes back after tab B toggles the theme and A reloads. The CONTRACT calls storage a convenience, so S3. Verified: tester (2 runs).

### 27. White on the accent colour fails contrast in dark
- `.tag.ref { background: var(--accent); color: #fff }` (310), the `.qbox:checked` tick (216) and the `.sw::after` knob (165): white on `#499fff` is 2.73:1 in dark (5.4:1 in light). CONTRACT asks that no component rule use a literal colour that reads in one theme only. Fix: `--fg-onbrand` on `--bg-brand`, or a dark token. Verified: tester (audit at 1280 and 400).

### 28. `--fg-3` text is below WCAG AA in both themes
- `#8e98a8` on white is 2.91:1; `#6f7a8c` on `#222731` is 3.45:1. Used for 11 px filter counts (`.chk .n`, 162), source URLs (`.dl .url`, 378) and placeholders (69). The badge count on its 22 % white layer is about 3.0:1 in dark. Verified: tester.

### 29. At 400 to 520 px the sticky header takes three rows (130 px)
- The narrow block (394) moves only the search to its own row. Logo + count pill + segs + theme + badge need about 512 px, so the theme button and badge wrap to a second row and the search to a third. The header then uses 16 % of an 800 px tall phone screen and pushes every sticky offset to 130 px. Verified: tester (rects) and orchestrator (`--hdr-h` 130 px).

### 30. Below 760 px the header Tab order does not match the visual order
- `.srch { order: 5 }` (394) moves the search visually to row 3 while the DOM keeps it before `.hdr-r`. Tab goes logo, Browse, Compare, search (row 3), theme (row 2), badge. Verified: tester.

## S4 notes

### 31. One slider step below the maximum hides every device with no price or no weight
- `filtered` (929 to 930) requires a non-null value once the slider leaves "Any": 134 → 111 devices at $3,450 (22 have no MSRP), 134 → 119 at 1,420 g (13 have no weight), with no cue. The code intends it; a product decision.

### 32. Queue "Clear" also clears the Browse reference; removing the reference device moves the reference
- `clear-queue` (1429) sets `refId = null`; `removeQ` (812) moves it to the next queued device. A reference chosen for browsing is lost when the compare list is emptied. Combined with finding 6, the next added device becomes a hidden reference.

### 33. Range sliders have no `aria-valuetext`
- `range` builder (886), `syncRanges` (913): a screen reader hears "3500" where the label says "Any".

### 34. `#stage3d` carries an `aria-label` on a `div` with no role
- `sizePanelHtml` (1061). Most screen readers ignore a name on a generic element; the slices are `aria-hidden`. The preset chips do give a keyboard alternative.

### 35. `.qbox` renders at 14×14 px
- `input[type="checkbox"]` (71, specificity 0,1,1) beats `.qbox` (214, 0,1,0). Touch targets under 24 px also include `.refb`, `.xbtn`, chips and `.sv` buttons (listed in the responsive report).

## Observations from the testers (not defects)

- 3D angles, the row limit and the narrow filter panel state are not saved. The CONTRACT says the drag "stores the angles on release"; the code stores them in memory only.
- `delta()` returns no pill when the reference value is 0 (NPU "None", 0 trackpads), not even "= 0%".
- The empty Compare heading reads "Compare 0 handhelds". The legend weight for an external-pack device lacks "with pack" while the grid shows it.
- Dropdown sub-lines repeat the chip name when the variant equals the SoC name ("Ryzen 7 7840U · Ryzen 7 7840U").
- 46 sheets show data notes with internal field names and the word "null" ("stick_type stays null"). This is data wording, not rendering.
- SSD cells show lowercase "not stated" for `form_factor: "other"` while `SSD_LABEL.other` is "Other"; Sticks shows "—" where the filter says "Not stated".
- Thickness formats differ: tile "24.2 / 42.3 mm", Closed row "29.8/37.5 mm".
- An unknown hash with stored state opens the stored route, not Browse. `{"v":3}` with no queue gives an empty queue. `"f":{"usb4":"no"}` turns the USB4 filter on (`!!`).
- No control returns the theme to "follow the system" after the first toggle.

## Not covered

- The claude.ai artifact viewer wrapper and its CSP: only the local full document was tested. The `[hidden]` rule, safe-area insets and the viewer's `:root` padding were not exercised.
- Firefox, Safari, and real touch devices. Only headless Chromium 154 with emulated viewports and mouse-driven pointer events.
- Screen readers. Accessibility checks were code-level (names, roles, states, contrast, tab order).
- The build scripts and data correctness against vendor pages. The testers compared the UI with the inlined data only.

## Suggested fix order

1. CSS only, low risk: findings 2, 3, 7, 15, 11, 27, 35 (dropdown grid template, slot dropdown anchor, `overflow-wrap`, `toggleAttribute`, on-brand tokens, checkbox size).
2. One-line logic: 10 (rounding), 6 (`afterRef()` in `addQ`), 12 (keep the loaded theme), 21 (plural).
3. Layout below 900 px: 1 and 4 (widen the `scroll` band to about 900 px, or drop the sticky offset inside the scroll container and make the device column sticky instead), 29 and 30 (shorten the header below 760 px and move the search in the DOM).
4. Reference model: 5 (filter the pinned reference, or show it as "pinned, outside filter" and count it), 22, 32.
5. Lookup guards: 9, 13, 14 (`Object.create(null)` maps, a `hasOwn` check in `loadState`, Browse fallback on an unknown hash change).
6. Focus management: 8, 24, 25 (restore focus by id after every re-render, as the sort handler does; move focus to the new screen's heading in `go()`; close other layers on `focusin`).
7. Popover: 16, 17 (close on scroll or reposition; move focus into the dialog and return it on close).
8. Design calls: 18, 19, 20, 26, 28, 31, 33, 34.

The exact repro commands for each finding are in the raw reports; they are plain Playwright calls and can become `@playwright/test` specs once the repo has a node toolchain.

## Defects found in the re-test (fixed the same day)

The four re-testers found eleven side effects of the new popover, focus, list-note, sticky-column, token and scroll-wrapper code. All eleven were fixed and re-verified by the orchestrator on the final build. The re-testers ran on intermediate builds, so the orchestrator re-ran the items that changed afterwards (R1 to R11).

| # | Severity | Defect | Fix |
|---|---|---|---|
| R1 | S3 | The popover painted over the sticky header while its value had slid under the header (the close test used the viewport top, not the header bottom) | `placePop()` closes when the value's bottom is above the header's bottom, and never places the box above the header |
| R2 | S3 | When the popover closed by itself on scroll or resize, focus dropped to `body` because `#pop` held focus | `closePop()` returns focus to the value when the popover had focus |
| R3 | S4 | "← Back to list" could focus a target outside the viewport (the list bar after a Compare-opened sheet, or the opener row once it was pinned as the reference); the next Tab then jumped the page | `go()` scrolls the focus target into view (`block: "center"`) when it is under the header or below the viewport |
| R4 | S3 | The hidden-rows note read "1 identical rows hidden" | `plural()` in `gridHtml` |
| R5 | S3 | After a Compare remove, focus went to the first column's remove button instead of the column that took the removed one's place | `restoreFocus` uses the queue order before the removal |
| R6 | S3 | Every Compare re-render reset the grid wrapper's horizontal scroll to column 1, so the restored focus target sat outside the wrapper at phone widths | `renderCompare` keeps `scrollLeft` across the re-render, and `focusId` scrolls the wrapper so the focused control is inside it |

## Features added after the fix pass (same day)

The user then asked for a homepage with a reference guide, a quick search on Browse, filters for almost every spec, cards as the default layout, and an answer to why the GPD fold consoles drew their screens wrong.

|---|---|

| Quick search (`#fq`) | Filters the list by name, brand, chip, chip id, GPU name or platform codename. All tokens must match. |
| Facet filters | 47 facets in 8 collapsible groups: multi-select lists with parts-picker counts, must-have flag lists, and 17 dual-range sliders. Option lists and slider bounds come from the data. Active filters show as removable chips. The panel moves between the sidebar and the narrow top panel without losing state or focus. |
| Cards by default | New visitors and migrated v3 users get cards. Storage moved to `handheld-atlas:v4`; v3 filters migrate. |
| Clamshells drawn open | The data stores a clamshell's closed footprint, and the old renderer drew that footprint as one slab with the screen nearly filling it, so a Win Max 2 looked like a tablet. Verification: three Opus testers checked every facet count against the data in five filter states, 14 result sets, all 17 sliders, quick search, chips, persistence, migration and corrupt storage; all 28 clamshells across sheets, cards and 224 Compare renders (2 × closed height and 1 × width, 0.00 % error); non-clamshell renders byte-identical to commit `a3f9fa1`; 1,795 popovers and 134 sheets at 1280 and 400; 138 width, theme and screen combinations without horizontal scroll; and contrast for every new text and UI pair in both themes. They found 16 issues (2 S2, 8 S3, 6 S4); all 16 were fixed and re-verified by the orchestrator on the final build:

- A device with two PCIe 4.0 slots counted twice in the "SSD interface" count (values are now unique per device).
- A long search chip widened the page at 400 to 760 px (the filter bar now has a `minmax(0, 1fr)` column and the chip truncates; the box takes at most 80 characters).
- The guide anchor scrolled under the sticky header (scroll margin), an option unticked past "Show more" vanished with focus (it stays until the list folds), the "Show N more" count, focus after the last chip, focus across the 760 px breakpoint, range labels wrapping in the sidebar, the chips row role, the summary focus ring, a one-way drag when both thumbs meet, the hero focus ring offset, the guide example styling, and the 3D clamshell screen.

Follow-up: the user reported that the GPD Win Max 3 screen should be edge to edge. Its closed footprint (207 × 180 × 34 mm) includes the 33 mm battery module on the front edge; the body without modules is 207 × 147 × 34 mm (GPD tech specs). The open drawing had copied the full footprint as the lid, which added 33 mm of false bezel. The schema gained `dims_mm.without_battery` (sourced in both Win Max 3 records), and the lid now uses it: the 9.06-inch screen sits with 6 mm side and 12.4 mm top and bottom bezels, and the module draws as a shaded strip on the deck's front edge. All 28 clamshell sheets were re-checked; the other 26 are unchanged.

Follow-up: the user reported that the Compare page showed clamshells as a block without a screen while the sheet looked right. Two causes: the 2D Compare views drew every screen as a faint 1 px outline with no fill, so the bezel did not read, and the 3D view drew clamshells closed with no screen. 2D screens now take a 22 % tint of the device colour with a stronger edge, and 3D draws clamshells open with the screen on the lid. Scale checks are unchanged (Win Max 3: 207 × 327 mm open).
