# New features to verify (read after BRIEF.md; this file overrides BRIEF.md where they differ)

The page under test is `http://127.0.0.1:8765/index.html`, rebuilt from `/home/n0k0m3/Programming/handheld-atlas/site/src/index.html`. The rules in `/home/n0k0m3/Programming/handheld-atlas/site/CONTRACT.md` were updated for these features; read its "Design notes" section.

## What changed since BRIEF.md was written

- **Storage key is now `handheld-atlas:v4`.** The shape is `{v:4, queue, refId, sortK, sortDir, f:{q, sel:{facetKey:[values]}, rng:{facetKey:[lo,hi]}}, groups, layout, hideSame, sizeOpen, sizeTab, sizeView, sizeMode, rx, ry, theme, route, detailId}`. A v3 entry migrates on first load: `brands`, `status`, `sticks` become `sel`, `usb4:true` becomes `sel.ports:["usb4"]`, `maxPrice`/`maxWeight` become `rng.price`/`rng.weight`, and the stored layout is dropped so cards apply.
- **Clean state recipe (important):** `goto` the target hash, wait 200 ms, `localStorage.clear()` (then seed with `localStorage.setItem('handheld-atlas:v4', ...)` if needed), then `reload()`. Never change the hash after seeding and before the reload: a hash change saves the in-memory state and overwrites your seed.
- **Four screens.** `main#scr-home` (`#home`), `#scr-browse` (`#browse`), `#scr-compare`, `#scr-detail`. A fresh visitor lands on Home. The logo `#logo` goes to Home. On Home both header segs read `aria-pressed="false"`. Focus targets after a user route change: `#home-h1`, `#browse` keeps the old rule (opener row or `#lbar`), `#cmp-h1`, `#dt-h1`.
- **Home** holds a hero, stats (`#home-n`, `#home-socs`, `#home-traced`, `#home-date`), three cards, a reference guide `section#guide-ref` with five steps, a "Compare sizes" guide, and "About the data". The "How to set one" link is `href="#guide-ref"`: it must scroll to the guide and leave `#home` in the address. The guide's examples are the real components without `data-id`; they must not react to the queue or the reference (for example the demo "Add to compare +" must not turn into "List full").
- **Cards are the default layout** for a fresh visitor and after a v3 migration. The table is still one click away (`#lay-table`).
- **Browse quick search** `input#fq` above the list filters by name, brand, variant, chip, chip id, GPU name and platform codename. All tokens must match. It shows as a chip "Search: …".
- **Facet panel** `#fpanel` with 47 facets in 8 `details.fsec` groups (`#fs-general`, `#fs-performance`, `#fs-memory-storage`, `#fs-display`, `#fs-size-weight`, `#fs-battery`, `#fs-controls`, `#fs-connectivity`). General and Performance start open. A group with saved filters opens on load. Group badges `#fsn-<group>` count active facets.
  - It sits in `aside#side` from 760 px. Below 760 px the same node moves into `#topf-b` (toggle `#tf-toggle`, summary `#tf-sum`).
  - **multi** facets (checkbox list, OR inside the facet): checkbox `#f-<key>-<slug>`, count `#fn-<key>-<slug>`. A device matches when it has any selected value. Multi-valued attributes (RAM options, factory storage, SSD slots, card slots, OS) match on any overlap. "unknown" is labelled "Not stated". Long lists show 8 options and a `#fmore-<key>` "Show N more" toggle; checked options always show.
  - **all** facets (checkbox list, AND, labelled "must have all"): `disp` (VRR, HDR, touch), `ctlf` (gyro, haptics, trigger lock, keyboard, detachable), `ports` (usb4, ocu, video, usba, jack, dc, xg), `extra` (fingerprint, removable battery).
  - **range** facets (dual slider): `#f-<key>-lo`, `#f-<key>-hi`, label `#f-<key>-l` ("Any", "≥ x", "≤ y", "x – y"), fill `#f-<key>-fill`. Keys: price, cpu, st, g3d, cores, tdp, npu, ramspeed, size, hz, weight, width, height, thick, wh, charge, usbc. Bounds come from the data rounded to the step. A range that is not the full span excludes devices with no value; the list bar note `#lbar-x` says "N without <x> hidden".
  - **Counts** work like a parts picker: an option's count is the number of devices that pass every other active filter and have that option (for an "all" facet: that also have every flag already selected in it). Options with 0 get class `zero`.
  - Facet keys and value sources: brands, status, form (form_factor), year (release_date year or unknown), price (msrp_usd), os (normalised Windows / SteamOS / Linux / Other), maker (SoC vendor; Valve/AMD counts as AMD), soc (soc_id, labelled with the chip name), platform (SoC codename), cpuarch (SoC cpu_arch with "/ Zen Nc" dropped), gpuarch, gpu (iGPU name), cpu/st/g3d (PassMark), cores, tdp (tdp_w.max), npu (npu_tops), ram (sizes_gb), ramtype, ramspeed, ssd (slot form factors or none), pcie (slot PCIe gen), cap (capacities_gb), card (expansion), size, res, panel, hz, disp, weight (measured else stated), width/height/thick (dims_mm.handheld), wh, charge, pack (battery.external), sticks, trig, pads (trackpads), rear (rear_buttons), ctlf, ports, usbc (count of USB-C class ports incl. USB4/TB), wifi, bt, extra.
- **Active-filter chips** `#fchips` above the list: `button.fchip#fx-<key>[-<slug>]` with a ×, plus `#fx-clear` "Clear all". Removing a chip moves focus to the next chip, else `#fq`. "Reset all" `#f-reset` sits in the panel header; the empty state's reset button still works.
- **Clamshells (28 devices: GPD Win Max 2 and 3, Win Mini, AYANEO Flip family, OneXPlayer G1)** store their closed footprint. The Compare front and back views, the card silhouette and the sheet outline draw them **open**: a lid path (`path.lid`) of the same footprint above, the deck below, a dashed `line.hinge` between, and the screen rect in the lid. The Compare view box height is twice the closed height. Legends, tiles, the dimension lines on the sheet (the height line marks the deck only) and every number stay on the closed size. Top and side views are unchanged (no lid). A note `.dnote` explains it under the Compare size panel (when a clamshell is queued) and on the sheet. Sliders (GPD Win 4, AYANEO Slide) are not clamshells and render as before.
- `README.md` and `CONTRACT.md` describe all of the above.
